# Peach 115 文件查询接口

本接口供 Peach 服务端按路径查询一个 115 文件的标识。默认关闭；配置不完整时拒绝查询，不改变已配置的其他接口和 115 授权。

启用时需要通过服务端环境配置以下字段：

| 变量 | 用途 |
| --- | --- |
| `PEACH_115_TOKEN` | 独立随机服务令牌，至少 32 字节；不要复用 115 令牌或放入 URL |
| `PEACH_115_ACCOUNT_ID` | QMediaSync 中已授权的 115 账号 ID |
| `PEACH_115_ROOT` | 允许查询的 115 绝对目录，例如 `/JAV` |

为令牌选择高熵随机值，通过受保护的部署配置提供，限制读取权限，不要提交到 Git。接口可返回提取码，只应在可信网络使用，并对服务间连接启用 TLS 或等效的隔离保护。原有 QMediaSync 接口的访问控制独立于该接口，应另行检查网络暴露。

## 请求与响应

`POST /internal/peach/115/resolve` 使用 `Authorization: Bearer <服务令牌>`，请求体为 JSON：

```json
{"path":"folder/movie.mp4","size":123456}
```

`path` 是相对于授权根的文件路径；`size` 是账本记录的字节大小。接口不接受账号参数、查询字符串、绝对路径、点路径段、反斜杠和百分号。必须唯一取得普通文件且返回的完整路径、大小和提取码有效，才返回文件 ID、提取码和大小。接口遵循项目的 `APIResponse` 契约：HTTP 200 下以 `code=200` 表示成功、`code=500` 表示拒绝或查询失败；调用方必须检查 `code`，失败时走原播放路径。

接口响应禁止缓存。不要将令牌、提取码、文件完整路径、115 原始响应或签名直链写入日志。现有的历史日志不会自动清理；其他服务、反向代理和既有入口的日志及权限仍需单独审查。路径和大小一致不能证明同路径同大小替换后的文件身份没有变化，调用方应对缓存设置有效期并在身份变化或解析失败后回退。
